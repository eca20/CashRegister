## D10 — Verification-driven corrections

- The initial test assertion used an invalid TypeScript overload. Corrected to
  pass an Error constructor; strict type checking then passed.
- Core/CLI tests passed, but HTTP tests initially could not bind loopback in the
  sandbox (EPERM). Running with local-network permission resolved that environment
  issue; no application behavior was changed to bypass a test.
- All 30 Node tests passed, but six browser checks failed with a blank page. The
  browser trace identified `React is not defined`: Vite was not discovering the
  separate frontend JSX configuration. Added `web/tsconfig.json` extending that
  configuration. This was an assistant-generated integration defect, found by
  exercising the production build in a real browser.
- CLI initially loaded an entire file before checking its size. Changed to bounded
  reads of at most limit + 1 bytes, so the limit also controls read-buffer memory.
- Added a repository-local Prettier configuration to avoid inheriting machine-local
  formatting preferences.

## D13 — Ed's correction: the page is the register

Ed judged the original AI-generated frontend functionally sufficient but visually
lacking, and requested a 2000s skeuomorphic revision. He explicitly ruled out a
picture of a register sitting on a wood counter: **the page itself functions as
the register**. The accepted plan applies materials to usable controls and page
surfaces. Literal appliance outlines, scenery, drawers and hardware illustrations
were excluded because they would compete with a fluid desktop/mobile interface.

The assistant replaced the minimal frontend with CSS plastic/metal surfaces,
recessed green amount displays, raised keys and paper receipts. No generated
image, decorative drawer or fixed perspective composition was used. This is a
human-directed modification of AI output; Ed has not claimed line-level code
authorship or completed code review.
